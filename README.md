# Kotoba Writer iPad — build 9

AI軽推敲を「AI誤字脱字修正」に変更した版です。

## build 9の変更
- 誤入力・誤変換・文字抜けだけを最小限修正するようAIへの指示を変更。言い回し・語尾・語順・句読点の調整は対象外です。
- 固有名詞・造語や、誤りか判断できない表現を推測で変えないよう指示。
- 「全文を選択」で全ページの本文をまとめて選択・コピーできます。選択専用画面から「選択範囲の誤字・脱字を確認」へ進めます。
- 選択範囲、または現在の段落を確認します。長文は800文字程度ずつ分割して順に処理し、完了後に候補を見て反映します。全文の処理には時間がかかります。
- 「中止」は現在の区間の処理が終わると停止します。途中結果は反映しません。
- 全文選択画面は選択・コピー専用です。本文の編集は元の画面で行います。
- AI連携の模擬応答テスト7項目で、全文の分割、候補確認、字下げ保持、反映、取り消し、中止、生成打ち切り、新しい編集の保護を確認しました。
- 字下げや末尾改行を削除する処理を廃止。生成が長さ制限で途中終了した場合は反映できないようにしました。
- AIモデルは従来と同じ端末内モデルです。AIの判断には誤検出・見落としがあります。実モデルの修正精度は今回未検証です。

- Chromiumで全文選択からAI確認画面への移動を追加確認しました。

以下はbuild 8から引き継いだ変更・検証です。

## 修正内容
- 縦書きの改行を明示的なBR要素で配置。連続改行・文中改行でも次の列の先頭にカーソルを置きます。
- 入力前の紙のスクロール位置を保持し、入力による不要な移動を戻します。カーソルが見えない場合だけ必要な量をスクロールします。
- 画面のパン（visualViewportのscroll）から自動スクロールを再発火しないように変更しました。
- 日本語変換中は編集DOMを作り直さず、紙の位置を保持します。
- 本文保存・コピー・貼り付けには通常の改行文字を使用します。
- 既存の保存キーは維持しています。

## 更新手順
1. 現在の本文を「TXT保存」で保存します。
2. このZIPを展開します。
3. 同じGitHub Pagesリポジトリの index.html、sw.js、manifest.webmanifest を上書きします。
4. GitHub Pagesの更新完了後、同じURLをオンラインのSafariで開き直します。秘匿モードがONの場合はOFFにして更新を読み込みます。
5. 画面下の「Kotoba Writer build 9」を確認します。build 8以前のままなら更新はまだ反映されていません。再読み込みしてください。
6. ホーム画面のアプリを使う場合は、一度閉じて開き直してください。更新後は必要に応じて秘匿モードをONに戻せます。

このZIPの作成だけでは公開ページは更新されません。本文保存前にSafariのサイトデータを削除しないでください。

## 開発者向け
通常利用にnpmや追加パッケージは不要です。
`npm install` 後、`npm test` でDOMテスト。`npm run test:proofreading` でAI連携の模擬応答テスト。
`npx playwright install chromium` 後、`npm run test:browser` でブラウザテスト。
既存のChromiumは KOTOBA_BROWSER_EXECUTABLE で指定できます。
テスト用フォントはテストサーバーから配信し、製品コードは外部フォントを取得しません。
