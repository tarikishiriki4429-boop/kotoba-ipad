# Kotoba Writer iPad — build28

## 全文操作の軽量化
全文画面での変更は本文データと下書きへ直ちに反映し、背後の原稿ページは画面を閉じるときにまとめて更新します。クリップボード操作の重複実行を抑制し、操作待ち中に閉じて開き直した場合は古い貼り付けを反映しません。

## AI準備時の画面停止対策
AIライブラリの読み込み・初期化・推敲を専用Workerへ移動しました。準備中も編集画面の処理を続けられます。「準備を中止」で読み込みを停止し、再試行できます。準備前に下書きを保存します。
これはモデルの容量を小さくする変更ではありません。端末のメモリ不足によるSafariの再読み込み・終了まで防ぐ保証はなく、iPadでの確認が必要です。Worker内WebGPUを利用できない環境ではエラーを表示します。

## 更新時に必須のファイル
**ai-worker.jsを必ずindex.htmlと同じ場所へ追加してください。** index.html、sw.js、manifest.webmanifest、licenses.html、各告知ファイル・licensesフォルダーも一緒に更新し、再読み込み後にbuild28を確認します。ZIPを一段余分なフォルダーの中に配置しないでください。
事前に原稿をTXT保存してください。ブラウザデータを削除する必要はありません。オンラインで更新後、必要に応じAIを準備し直してください。

約2.1万字の全選択・コピー・切り取り・貼り付けを20回反復し、本文一致と背後ページの再構築0回を確認。重複25回の貼り付け要求を1回に制限し、古い画面への結果の反映を防ぐ試験を通過しました。AIは実Workerと模擬エンジンで画面応答・中止・エラー・再試行を検証し、実WebLLM配布モジュールのWorker内読み込みも確認しました。実GPU推論・iPad実機は未検証です。
